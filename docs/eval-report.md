# 检索质量评测报告

本报告用于量化「中文分块」与「中文向量」两项改动的实际效果，并给出可复现的步骤。

## 1. 评测设置

| 项 | 取值 |
|---|---|
| 语料 | 5 篇中文短文档（部署 / 配置 / 安全 / 检索原理 / 性能调优），共约 1,100 字 |
| 问题 | 10 个，每题对应一个只在某篇文档中出现的关键词 |
| 向量维度 | 256 |
| Top-K | 3 |
| 分块大小 | 统一 120 字符（两种策略使用相同预算，保证可比） |
| 判定方式 | 命中关键词即视为召回正确片段，记录其名次 |

> 说明：这是**简化评测**。严格做法应由人工标注「正确片段 ID」再计算 Recall@K；
> 用关键词判定会受同义词与措辞影响，但足以在同等条件下比较策略优劣。

## 2. 结果

| 分块策略 | 向量策略 | Hit@1 | Hit@3 | 整句结束率 |
|---|---|---|---|---|
| FixedSize(120) | Hashing（原实现） | 4/10 | 8/10 | 50% |
| FixedSize(120) | CJK-bigram（本次新增） | **7/10** | **10/10** | 50% |
| ChineseSplitter(120,20) | Hashing（原实现） | 4/10 | 7/10 | **100%** |
| ChineseSplitter(120,20) | CJK-bigram（本次新增） | **7/10** | **10/10** | **100%** |

## 3. 结论

1. **中文向量是主要瓶颈。** 原实现用标点切词，中文整段会变成一个超长 token，
   相似度实际退化为字符三元组匹配。改为「单字 + 相邻二字」特征后，
   Hit@1 从 4/10 提升到 7/10，Hit@3 从 8/10 提升到 10/10。

2. **分块策略不改变命中率，但决定证据可读性。** 在只有 2 块/篇的语料上，
   句子是否对齐不影响"命中哪篇文档"，因此 Hit@K 没有变化；
   但它把「整句结束率」从 50% 提到 100%，直接影响用户看到的证据质量。

3. 两项改动是**正交**的，组合后达到 7/10 与 10/10，且证据全部为完整句。

## 4. 复现方式

```bash
mvn -q -DskipTests compile \
  org.codehaus.mojo:exec-maven-plugin:3.6.3:java \
  -Dexec.mainClass=org.playground.RetrievalBenchmark
```

评测逻辑见 `src/main/java/org/playground/RetrievalBenchmark.java`，
语料与问题直接内联在该文件中，便于改动后重跑对比。

## 5. 已知局限

- 语料规模小（5 篇文档），结论只说明趋势，不代表大规模语料下的绝对表现。
- 关键词判定无法区分"命中了正确片段"与"命中了包含关键词的其他片段"。
- 哈希向量本身是离线演示方案，并非生产级语义向量；
  本报告的对比只在同一向量方案内部成立。
- 未评测答案质量，只评测检索环节。抽取式生成器的输出本身不代表模型能力。
